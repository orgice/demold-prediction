# CSV 데이터 이름 변경·삭제 API 요청 (프론트 → 백엔드)

작성 2026-11-18 · 프론트 화면: 회차 상세 › 설정 › **CSV 데이터** 카드 (`src/pages/PourSettings.tsx`)

## 왜 필요한가

회차 설정에서 CSV를 추가할 수만 있고, 잘못 올린 CSV를 지우거나 알아보기 쉬운 이름으로 바꿀 방법이 없습니다.
프론트는 아래 계약대로 화면을 만들어 두었고, 지금은 브라우저 목업(`src/api/uploadsMock.ts`)으로 동작합니다.
API가 준비되면 `src/api/uploads.ts`의 `UPLOADS_IS_MOCK`를 `false`로 바꾸면 바로 연결됩니다.

## 1. `upload_log` 컬럼 추가

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `label` | `VARCHAR(100) NULL` | 사용자가 붙인 표시 이름. 없으면 화면은 `filename`을 보여 줌 |
| `sensors` | `VARCHAR(500)` (쉼표 구분 MAC) | 이 업로드에 들어 있던 센서. 지금은 없어서 회차와 **기간으로만** 연결하고 있음 |

`GET /api/uploads` 응답에 `label`, `sensors`(문자열 배열)를 추가해 주세요.
`sensors`가 생기면 프론트는 "회차 기간과 겹침 **그리고** 회차 연결 센서 포함"으로 더 정확히 거를 수 있습니다.

## 2. `PATCH /api/uploads/{id}` — 표시 이름 변경

```json
요청  { "label": "B동 슬래브 1차 (재측정)" }   // null 또는 "" 이면 원래 파일명으로
응답  UploadLog (GET /api/uploads 의 한 항목과 같은 모양, label 포함)
```

- 원본 파일명 `filename`과 원본 행의 `src_file`은 바꾸지 않습니다 (추적용).
- 100자 제한, 앞뒤 공백 제거. 없는 id는 404.

## 3. `DELETE /api/uploads/{id}` — 이 CSV로 저장된 데이터 삭제

```json
응답  { "rows_deleted": 1234, "sensors": ["9288"], "period_start": "2026-10-09T08:00:00", "period_end": "2026-10-19T08:00:00" }
```

처리 순서 제안:
1. `upload_log.kind`에 따라 `pressure` 또는 `moisture`에서 이 업로드가 저장한 행 삭제 (`src_file = filename` 기준이면 아래 4절의 같은 파일 이름 문제가 있음, `upload_id` 기준 권장). `rows_inserted = 0`이면 이 단계를 건너뜀
2. 지운 행의 MAC·시간 범위에 해당하는 `sensor_10min` 칸을 다시 집계 (남은 원본으로 재계산, 원본이 없어진 칸은 삭제)
3. `upload_log` 행 삭제
4. `maturity.clear_cache()` (업로드 때와 동일)
5. 한 트랜잭션으로 처리, 실패 시 전부 되돌림

## 4. 협의가 필요한 점

- **같은 파일 이름을 두 번 올린 경우 (실제 로컬 DB에 있음)**: `upload_log` id 1·8이 둘 다 `p_260806.csv`이고, 1은 767,076행 저장, 8은 0행(재업로드)입니다.
  `src_file = filename` 기준으로 지우면 **id 8을 지울 때 id 1의 데이터까지 지워집니다.**
  - 제안: 원본 행(`pressure`/`moisture`)에 `upload_id`를 기록하고 그 기준으로 지우기. 기존 데이터는 `src_file`이 같은 업로드 중 `rows_inserted > 0`인 가장 이른 업로드에 연결해 옮김.
  - 그 전까지는 `rows_inserted = 0`인 업로드 삭제는 `upload_log` 행만 지우도록 처리해 주세요 (프론트도 그렇게 안내함).
- **같은 행이 여러 파일에 있을 때**: `row_hash` 중복 제거 때문에 같은 행은 처음 올린 파일 이름(`src_file`)으로만 저장됩니다.
  - A 파일과 B 파일이 기간이 겹치면, A를 지울 때 B에도 있던 행까지 사라집니다. 반대로 B를 지우면 겹친 행은 남습니다.
  - 제안: 삭제 응답이나 확인 단계에서 "다른 업로드와 겹치는 행 수"를 알려 주거나, 원본 행에 `upload_id`를 기록하는 방식으로 바꾸는 것.
- **권한**: 로그인 목업 기준 '편집' 이상만 가능하게 할지. 프론트는 아직 역할로 버튼을 숨기지 않습니다.
- **삭제 이력**: 되돌릴 수 없는 작업이므로 누가 언제 지웠는지 남길지.
