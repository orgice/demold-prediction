# DESIGN.md — FormCast 웹앱 채널톡 스타일 적용 가이드

거푸집 탈형 시점 예측 웹앱(`webapp/frontend`)에 채널톡의 UI·UX 톤을 입히기 위한 디자인 기준서다.
화면을 고치는 사람(또는 AI 에이전트)은 이 문서의 토큰과 규칙만 보고 작업한다.

- **기준**: 채널톡 공개 디자인 시스템 Bezier(`channel-io/bezier-react`의 `bezier-tokens`, 2026-11-12 main 기준 값)
- **범위**: 색·글자·간격·모서리·그림자·움직임·컴포넌트 모양·화면 틀. 기능, API, 화면 구성 항목은 바꾸지 않는다.
- **표기**: `Bezier` 표시는 저장소에서 확인한 값, `FormCast 결정`은 이 프로젝트에 맞춰 정한 값이다.
- **주의**: 채널톡의 로고·서비스명·일러스트·아이콘 원본은 쓰지 않는다. 색과 형태의 규칙만 따른다. `@channel.io/bezier-react` 패키지를 직접 설치할 경우 라이선스를 먼저 확인한다.

---

## 1. 디자인 방향

| 원칙 | 뜻 | FormCast에서 |
|---|---|---|
| 조용한 바탕, 또렷한 한 점 | 화면 대부분은 흰색·옅은 회색, 강조색은 한 화면에 한두 곳 | 주 버튼, 선택된 메뉴, 링크에만 파랑(`#5E56F0`) |
| 선보다 면 | 테두리 대신 옅은 회색 면과 약한 그림자로 구분 | 카드 테두리를 없애고 `ev-1` 그림자 사용 |
| 촘촘하되 답답하지 않게 | 본문 14px, 4px 단위 간격 | 표·KPI는 14px, 보조 설명 13px |
| 둥글고 부드럽게 | 6~12px 모서리, 150ms 전환 | 버튼 8px, 카드 12px, 모달 16px |
| 상태는 색 + 글자 | 색만으로 뜻을 전달하지 않는다 | 강도 미달 알림은 빨강 + 문구 + 아이콘 |

현재 화면과 가장 달라지는 점: 따뜻한 회색(`#f4f4f2`) → 중립 회색(`#F7F7F8`), 파랑 `#2a78d6` → 보라빛 파랑 `#5E56F0`, 짙은 청록 배너 → 옅은 파랑 면, 굵기 600 → 700.

### 2.2 글자·테두리·면 (Bezier)

| 용도 | 라이트 | 다크 |
|---|---|---|
| 글자 기본 `txt-black-darkest` | `rgba(0,0,0,.85)` | `rgba(255,255,255,.80)` |
| 글자 보조 `txt-black-darker` | `rgba(0,0,0,.60)` | `rgba(255,255,255,.60)` |
| 글자 약함 `txt-black-dark` | `rgba(0,0,0,.40)` | `rgba(255,255,255,.40)` |
| 테두리 `bdr-black-light` | `rgba(0,0,0,.08)` | `rgba(255,255,255,.12)` |
| 테두리 진함 `bdr-black-dark` | `rgba(0,0,0,.15)` | `rgba(255,255,255,.20)` |
| 눌림·호버 면 `bg-black-lighter` | `rgba(0,0,0,.05)` | `rgba(255,255,255,.08)` |
| 선택 면 `bg-black-light` | `rgba(0,0,0,.08)` | `rgba(255,255,255,.12)` |
| 비활성 | 불투명도 0.4 | 같음 |

`txt-black-dark`(40%)는 대비가 낮다. 플레이스홀더·보조 표기에만 쓰고 읽어야 하는 본문에는 쓰지 않는다.

## 3. 글자

- **글꼴 (FormCast 결정)**: `"Pretendard", "Inter", "Noto Sans KR", -apple-system, BlinkMacSystemFont, "Segoe UI", system-ui, sans-serif`
  Bezier 기본은 Inter + Noto Sans KR이다. Pretendard는 Inter 기반이라 인상이 같고 기존 산출물(PPT)과도 맞는다. 현재 `index.html`에는 웹폰트 불러오기가 없어 기기 글꼴로 보이므로, 적용 시 Pretendard 웹폰트를 추가한다.
- **굵기 (Bezier)**: 400과 700 두 가지만. 현재 코드의 `600`은 모두 `700`으로.
- **숫자**: KPI·표·그래프 축은 `font-variant-numeric: tabular-nums` 유지.

| 크기/줄높이 (Bezier) | 자간 | FormCast 용도 |
|---|---|---|
| 24 / 32 | -0.4px | KPI 숫자, 대시보드 배너 제목 |
| 22 / 28 | -0.4px | 페이지 제목 `h1` |
| 18 / 24 | 0 | 카드 제목 `h2` |
| 16 / 24 | -0.1px | 소제목 `h3`, 브랜드명 |
| 14 / 18 | 0 | **본문 기본**, 버튼, 표, 입력 |
| 13 / 18 | 0 | 보조 설명 `.small`, 라벨 |
| 12 / 16 | 0 | 배지, 주석 `.tiny` |
| 11 / 16 | 0 | 알림 개수 점, 그래프 표기 |

기본 글자 크기를 15px → 14px로 내린다. 긴 문장이 이어지는 곳(AI 상담 말풍선, 빈 화면 안내)은 줄높이 20px 이상으로 둔다.

## 4. 간격·모서리·그림자·움직임

- **간격 (FormCast 결정)**: 4px 단위 — 4 · 8 · 12 · 16 · 20 · 24 · 32. 카드 안쪽 20px, 카드 사이 16px, 페이지 좌우 24px(모바일 16px).
- **모서리 (Bezier 단계 중 선택)**: 배지 속 작은 요소 4 · 입력·작은 버튼 6 · 버튼·메뉴 항목 8 · 카드·팝오버 12 · 모달 16 · 알약 모양 `999px`.
- **그림자 (Bezier elevation)**: 카드 `ev-1` · 드롭다운·회차 선택 팝오버 `ev-3` · 모달 `ev-5`. 다크에서도 그림자를 유지하되 면 색 차이로 먼저 구분한다.
- **움직임 (Bezier)**: `150ms cubic-bezier(0.3, 0, 0, 1)`를 배경색·테두리·그림자·불투명도에 적용. 펼침(회차 카드 삼각형)은 300ms. `prefers-reduced-motion`이면 전환을 끈다.
- **쌓임 순서 (Bezier)**: 떠 있는 요소 1 · 팝오버 1000 · 모달 1100 · 토스트 1200 · 툴팁 1300. 현재 `10 / 20 / 50`을 이 값으로 맞춘다.

## 5. 화면 틀

채널톡 데스크는 왼쪽 메뉴 + 넓은 본문 구조다. 메뉴가 4개뿐이므로 2단계로 나눈다.

**1단계 (권장, 구조 유지)** — 지금의 상단 막대를 유지하고 모양만 바꾼다.
- 상단 막대: 흰 배경, 높이 56px, 아래 테두리 `--border`, 스크롤 시 `rgba(255,255,255,.9)` + `backdrop-filter: blur(20px)`.
- 메뉴 항목: 높이 32px, 모서리 8px, 글자 14px `--text-2`. 호버 `--hover`. 선택 시 배경 `--accent-bg` + 글자 `--accent` + 굵기 700.
- 본문: 최대 폭 1200px 유지, 배경 `--bg`, 카드는 흰색.

**2단계 (선택, `main.tsx` 수정 필요)** — 900px 이상에서 왼쪽 메뉴로 전환.
- 왼쪽 메뉴 폭 240px, 배경 `--bg`, 오른쪽 테두리 없음. 본문 영역은 흰색 면이 왼쪽 위 모서리 16px로 얹힌 형태.
- 900px 미만은 1단계 상단 막대 그대로. 현장에서 한 손으로 쓰는 화면이므로 하단 탭으로 바꾸지 않는다(그래프 영역 확보).

| `.bubble` (AI 상담) | 모서리 12px, 안쪽 10×14. 사용자: `--accent` + 흰 글자. 상담: `--surface-2`. 최대 폭 80%(모바일 92%) 유지. |
| `.chat-input` | 입력 높이 44px·모서리 12px, 보내기 버튼은 주 버튼. |
| `.empty` | 가운데 정렬, 제목 16px/700, 설명 14px `--text-2`, 버튼은 주 1개 + 기본 1개까지. |

공통: 키보드 포커스는 모든 조작 요소에 `box-shadow: 0 0 0 3px var(--accent-ring)`로 보이게 한다. 모바일에서 누르는 영역은 최소 36px 높이.

## 8. UX 규칙

1. **한 화면에 주 행동 하나.** 대시보드는 ‘새 타설 등록’, 회차 상세는 ‘저장’ 식으로 파란 버튼은 하나만.
2. **빈 화면·실패 화면에도 다음 길을 준다.** 진행 중 회차 없음 → 타설 이력·새 타설 등록 버튼. 조회 실패 → 빨강 알림 + ‘다시 시도’.
3. **예시 데이터는 사용자가 골랐을 때만.** 표시 중에는 화면 위에 cobalt 안내 띠(“예시 데이터입니다”)를 계속 둔다.
4. **확정되지 않은 값은 확정처럼 보이지 않게.** 가정 온도 기반 예측은 점선·`--text-2`·‘가정’ 배지. 보수적 시점은 보조 줄에.
5. **알림은 조용히.** 종 아이콘의 개수 점으로 알리고, 패널은 눌렀을 때만 연다. 메일은 ‘메일 초안 열기’로 적는다(자동 발송이 아님).
6. **즉시 반응.** 누르면 150ms 안에 눌림 표시, 400ms 넘는 조회는 뼈대(skeleton) 면(`--surface-2`)을 보여 준다.
7. **말투.** 짧은 해요체, 주어 생략, 버튼은 동사형 명사(“등록”, “다시 시도”, “전체 선택”). 오류는 원인 + 할 일 한 줄씩.
