# DESIGN.md — FormCast UI·UX 디자인 기준 및 변경 제안

거푸집 탈형 시점 예측 웹앱(`webapp/frontend`)의 화면 구조, 시각 스타일, 사용 흐름을 정리한 문서다.

- **개정일**: 2026-11-12
- **방향**: Linear의 정돈된 업무 화면 + SmartRock의 콘크리트 모니터링 흐름 + Grafana의 센서 탐색 방식.
- **시각 기반**: 기존 채널톡 Bezier 참고 색상·카드·간격 토큰을 유지하고 정보 우선순위를 개선한다.
- **문서 상태**: 코드와 README를 검토한 변경 제안이다. 실행 화면 사용성 검증 또는 고객 확정 요구사항으로 간주하지 않는다. 이 문서 개정만으로 UI가 구현되지는 않는다.
- **범위**: 대시보드, 타설 이력·상세, 센서 데이터, AI 상담의 UI·UX. 예측 계산과 임계값 자체는 변경하지 않는다.
- **표기**: 아래 `Bezier` 값은 기존 문서에서 이어받은 참고 토큰이며 이번 개정에서 외부 원본을 재검증하지 않았다. `FormCast 결정`은 프로젝트 적용 기준이다.
- **자산 사용**: 참고 서비스의 로고·일러스트·제품 화면을 복제하지 않는다. 외부 패키지 도입 시 라이선스를 확인한다.

## 1. 디자인 방향과 참고 서비스

### 1.1 사용자가 먼저 알아야 하는 것

1. 어떤 타설을 먼저 확인해야 하는가?
2. 해당 부재의 목표 강도에 언제 도달할 것으로 예상되는가?
3. 판단에 필요한 데이터가 충분하고 최신인가?

화면은 **상태와 예상 시각 → 근거 그래프 → 필요한 입력과 상세 정보** 순서로 읽히게 한다. 회차 비교는 유지하되 사용자가 필요할 때 진입하는 분석 흐름으로 배치한다.

### 1.2 레퍼런스와 적용 범위

| 서비스 | 참고 근거 | FormCast 적용 제안 |
|---|---|---|
| [Linear](https://linear.app/docs/display-options) | 목록·보드 전환, 그룹·정렬, 표시 항목 설정 | 상태별 타설 목록, 간결한 필터, 일정한 정보 배치. 외형의 주 레퍼런스 |
| [SmartRock Web](https://www.giatecscientific.com/products/software/smartrock-web/) | 타설 관리와 콘크리트 강도·온도 모니터링 | 현장 → 타설 → 센서 구조와 결과 중심 조회. 업무 흐름의 주 레퍼런스 |
| [Grafana](https://grafana.com/docs/grafana/latest/visualizations/dashboards/use-dashboards/) | 시간 범위, 변수·필터, 그래프 구간 확대 | 센서 화면의 공통 기간 선택과 탐색. 높은 정보 밀도는 분석 화면에 한정 |

위 서비스의 기능 설명과 FormCast에 대한 설계 제안을 구분한다. 모든 서비스의 화면을 그대로 결합하는 방식은 피한다.

### 1.3 공통 원칙

| 원칙 | 적용 |
|---|---|
| 조용한 바탕, 분명한 행동 | 흰색·중립 회색 바탕, 보라색 포인트는 주요 버튼과 선택 상태에 집중 |
| 결과를 먼저, 근거는 가까이 | 목표 도달 예상 시각을 상단에 두고 강도 그래프와 데이터 기준 시각을 연결 |
| 상태는 색 + 글자 | 예측 기준 도달·확인 필요·데이터 부족을 문구로 구분 |
| 예측과 승인을 구분 | ‘예측 기준 도달’을 ‘해체 승인 완료’로 표현하지 않음 |
| 입력으로 이어지는 안내 | 공시체 미입력·타설 시각 미확정 안내에서 해당 입력 화면으로 바로 이동 |
| 현장 가독성 | 본문 15~16px, 충분한 터치 영역, 숫자와 단위의 위계 분리 |

### 2.2 글자·테두리·면 (Bezier)

| 용도 | 라이트 | 다크 |
|---|---|---|
| 글자 기본 `txt-black-darkest` | `rgba(0,0,0,.85)` | `rgba(255,255,255,.80)` |

| 테두리 진함 `bdr-black-dark` | `rgba(0,0,0,.15)` | `rgba(255,255,255,.20)` |

## 3. 글자

- **글꼴 (FormCast 결정)**: `"Pretendard", "Inter", "Noto Sans KR", -apple-system, BlinkMacSystemFont, "Segoe UI", system-ui, sans-serif`
  Bezier 기본은 Inter + Noto Sans KR이다. Pretendard는 Inter 기반이라 인상이 같고 기존 산출물(PPT)과도 맞는다. 현재 `index.html`에는 웹폰트 불러오기가 없어 기기 글꼴로 보이므로, 적용 시 Pretendard 웹폰트를 추가한다.
- **굵기 (Bezier)**: 400과 700 두 가지만. 현재 코드의 `600`은 모두 `700`으로.
- **숫자**: KPI·표·그래프 축은 `font-variant-numeric: tabular-nums` 유지.

| 크기/줄높이 (Bezier) | 자간 | FormCast 용도 |
|---|---|---|
| 24 / 32 | -0.4px | KPI 숫자, 대시보드 배너 제목 |
| 22 / 28 | -0.4px | 페이지 제목 `h1` |
| 18 / 24 | 0 | 카드 제목 `h2` |
| 16 / 24 | -0.1px | 소제목 `h3`, 브랜드명 |
| 16 / 24 | 0 | **본문 기본**, AI 답변, 입력 |
| 15 / 22 | 0 | 일반 설명, 목록 본문 |
| 14 / 20 | 0 | 데스크톱의 조밀한 표, 보조 버튼 |
| 13 / 18 | 0 | 보조 설명 `.small`, 라벨 |
| 12 / 16 | 0 | 배지, 주석 `.tiny` |
| 11 / 16 | 0 | 알림 개수 점, 그래프 표기 |

본문 기본은 16px/24px을 권장한다. 데스크톱의 조밀한 표만 14px을 허용하고, 주요 시각·강도 숫자는 24~32px로 강조한다. 단위와 설명은 작은 크기로 분리한다.

## 4. 간격·모서리·그림자·움직임

- **간격 (FormCast 결정)**: 4px 단위 — 4 · 8 · 12 · 16 · 20 · 24 · 32. 카드 안쪽 20px, 카드 사이 16px, 페이지 좌우 24px(모바일 16px).
- **모서리 (Bezier 단계 중 선택)**: 배지 속 작은 요소 4 · 입력·작은 버튼 6 · 버튼·메뉴 항목 8 · 카드·팝오버 12 · 모달 16 · 알약 모양 `999px`.
- **그림자 (Bezier elevation)**: 카드 `ev-1` · 드롭다운·회차 선택 팝오버 `ev-3` · 모달 `ev-5`. 다크에서도 그림자를 유지하되 면 색 차이로 먼저 구분한다.
- **움직임 (Bezier)**: `150ms cubic-bezier(0.3, 0, 0, 1)`를 배경색·테두리·그림자·불투명도에 적용. 펼침(회차 카드 삼각형)은 300ms. `prefers-reduced-motion`이면 전환을 끈다.
- **쌓임 순서 (Bezier)**: 떠 있는 요소 1 · 팝오버 1000 · 모달 1100 · 토스트 1200 · 툴팁 1300. 현재 `10 / 20 / 50`을 이 값으로 맞춘다.

## 5. 화면 틀

현재 메뉴 4개에는 상단 내비게이션을 유지한다. 사이드바는 메뉴 확장 시 선택 사항이다.

**기본 구조** — 메뉴가 4개인 현재는 상단 막대를 유지한다. 본문의 정보 순서는 12장에 따라 개선한다.
- 상단 막대: 흰 배경, 높이 56px, 아래 테두리 `--border`, 스크롤 시 `rgba(255,255,255,.9)` + `backdrop-filter: blur(20px)`.
- 메뉴 항목: 높이 32px, 모서리 8px, 글자 14px `--text-2`. 호버 `--hover`. 선택 시 배경 `--accent-bg` + 글자 `--accent` + 굵기 700.
- 본문: 최대 폭 1200px 유지, 배경 `--bg`, 카드는 흰색.

**확장 시 선택 사항** — 현장·권한·보고서 메뉴가 늘어날 때 900px 이상에서 왼쪽 메뉴를 검토한다. 현재 필수 변경에 포함하지 않는다.
- 왼쪽 메뉴 폭 240px, 배경 `--bg`, 오른쪽 테두리 없음. 본문 영역은 흰색 면이 왼쪽 위 모서리 16px로 얹힌 형태.
- 900px 미만은 상단 막대를 유지하되 메뉴 줄바꿈과 터치 영역을 확인한다.

## 6. 컴포넌트 규칙

기존 클래스 이름 기준. 값은 FormCast 결정이며 형태는 Bezier 컴포넌트를 따른다.

| 클래스 | 규칙 |
|---|---|
| `.btn` | 높이 36px, 좌우 14px, 모서리 8px, 14px/700. 기본형: 테두리 없이 배경 `--hover`, 호버 시 `rgba(0,0,0,.08)`. |
| `.btn.primary` | 배경 `--accent`, 글자 흰색, 호버 `--accent-hover`. `filter: brightness` 제거. 한 화면(모달 포함)에 1개. |
| `.btn.danger` | 배경 `--bad-bg`, 글자 `--bad`. 삭제 확정 버튼만 빨강 채움. |
| `.btn.sm` | 높이 28px, 좌우 10px, 모서리 6px, 13px. 모바일에서 단독으로 눌러야 하는 버튼에는 쓰지 않는다. |
| `.btn:disabled` | 불투명도 0.4. |
| `.icon-btn` (종 아이콘) | 32×32, 테두리 없음, 호버 `--hover`, 켜짐 `--accent-bg` + 아이콘 `--accent`. `.dot-count`는 `--bad` 유지. |
| `input, select, textarea` | 높이 36px, 모서리 8px, 흰 배경, 테두리 대신 `box-shadow: 0 1px 2px rgba(0,0,0,.05), inset 0 0 0 1px rgba(0,0,0,.15)`. 포커스: `0 0 0 3px var(--accent-ring), inset 0 0 0 1px var(--accent)`, `outline: none`. 오류: 같은 형태에 orange. |
| `label.field` | 라벨 13px/700 `--text-2`, 입력과 간격 6px. 도움말은 12px `--text-3`. |

## 8. UX 규칙

1. **한 화면에 주 행동 하나.** 대시보드는 ‘새 타설 등록’, 회차 상세는 ‘저장’ 식으로 파란 버튼은 하나만.
2. **빈 화면·실패 화면에도 다음 길을 준다.** 진행 중 회차 없음 → 타설 이력·새 타설 등록 버튼. 조회 실패 → 빨강 알림 + ‘다시 시도’.
3. **예시 데이터는 사용자가 골랐을 때만.** 표시 중에는 화면 위에 cobalt 안내 띠(“예시 데이터입니다”)를 계속 둔다.
4. **확정되지 않은 값은 확정처럼 보이지 않게.** 가정 온도 기반 예측은 점선·`--text-2`·‘가정’ 배지. 예상 시점과 보수적 시점(90% 하한 기준)을 함께 읽을 수 있게 표시한다.
5. **알림은 행동으로 연결한다.** 종 아이콘과 펼침 패널을 유지하고, 확인이 필요한 항목은 본문 상단에도 요약한다. 메일은 ‘메일 초안 열기’로 적는다(자동 발송이 아님).
6. **즉시 반응.** 누르면 150ms 안에 눌림 표시, 400ms 넘는 조회는 뼈대(skeleton) 면(`--surface-2`)을 보여 준다.
7. **말투.** 짧은 해요체, 주어 생략, 버튼은 동사형 명사(“등록”, “다시 시도”, “전체 선택”). 오류는 원인 + 할 일 한 줄씩.

## 12. 화면별 변경 상세

### 12.1 대시보드

현재는 회차 선택·비교 기능이 앞에 있다. 변경안은 현장 담당자의 상황 확인을 먼저 지원한다.

```text
상단 메뉴: 대시보드 / 타설 이력 / 센서 데이터 / AI 상담
현장 선택 · 데이터 기준 시각                    [새 타설 등록]
확인 필요: 타설 시각 미확정 / 공시체 미입력 / 데이터 부족
진행 중 타설 목록                              [회차 비교]
선택 타설: 현재 예측 강도 · 목표 도달 예상 · 보수적 시각
강도 그래프 · 근거 보기 · 입력 바로가기
```

- 목록 열: 타설명 / 부재 / 경과 시간 / 현재 예측 강도 / 목표 도달 예상 / 확인 사항.
- 확인 사항에서 실제 작업으로 연결한다. ‘공시체 미입력’ → 공시체 결과 탭, ‘타설 시각 미확정’ → 타설 시점 확인 탭.
- 이전 회차 선택, 겹쳐 보기, 회차별 보기는 비교 화면 또는 펼침 영역에서 유지한다.
- 진행 중 회차가 없으면 최근 회차와 타설 이력·새 타설 등록 경로를 제공한다.
- 현재 코드의 ‘타설 후 28일 이내’ 판정은 구현 현황이며, 확정된 운영 정책으로 표현하지 않는다.

### 12.2 타설 상세

상단 요약 → 강도 그래프 → 관련 입력 → 온도·모델 상세 순으로 정보를 배치한다. 기존 탭과 기능은 유지하고 관련 위치에 바로가기를 둔다.

| 정보 | 표시 방식 |
|---|---|
| 현재 상태 | ‘예측 기준 미도달’, ‘예측 기준 도달’, ‘데이터 부족’처럼 구체적으로 표시 |
| 목표 시각 | 해당 부재 목표의 예상 시각과 보수적 시각을 함께 표시. 부재·기준 미설정이면 설정 안내 |
| 현재 강도 | 예측값임을 명시하고 MPa와 90% 범위를 함께 표시 |
| 28일 강도 | 현재 상태·목표 시각 다음의 보조 지표로 유지 |
| 보정 | ‘공시체 결과 반영됨 / 미입력’으로 표시. 배율·학습 정보는 상세로 이동 |
| 데이터 기준 | 예측 계산 시점과 마지막 센서 데이터 시점을 구별 |

강도 그래프의 기본 표시는 현재 추정·미래 예측·90% 범위·해당 목표 기준선·공시체 시험점이다. 최초 예측과 추가 기준선은 선택해서 표시할 수 있게 한다. 관측 온도로 계산한 강도도 **추정값**이며 실제 압축강도 시험점과 구분한다. 목표 도달 표시를 현장 승인 완료로 사용하지 않는다.

### 12.3 타설 이력

- 회차 이름 검색과 상태·부재 필터를 제공하고 조건 해제를 쉽게 한다.
- 수치 열은 오른쪽 정렬하고 단위를 머리글에 명시한다.
- 행 선택으로 상세 진입, 회차 비교 선택은 별도 체크박스로 구분한다.
- 모바일에서는 이름·상태·예상 시각 중심 카드로 요약하고 나머지는 상세에서 확인한다.

### 12.4 센서 데이터

- 온도·측압·수분 그래프가 하나의 기간 선택을 공유하도록 한다.
- 제공 가능한 위치 정보가 있으면 ‘벽체 상단 · 센서 01’처럼 표시하고 MAC 주소는 상세로 이동한다. 위치 정보가 없으면 기존 식별자를 사용하며 임의로 생성하지 않는다.
- 마지막 수신 시각과 결측 구간을 표시한다. 결측을 0이나 정상 측정값으로 채우지 않는다.
- 그래프 확대·기간 초기화와 센서 필터를 같은 위치에 둔다.
- CSV 업로드 이후 데이터 상태를 표시한다. 실제 자동 연동이 없는 상태에서 ‘실시간 연결됨’이라고 쓰지 않는다.

### 12.5 AI 상담

- 별도 상담 페이지를 유지하고 타설 상세에 ‘이 타설에 질문하기’를 추가한다.
- 선택 회차 ID를 전달하고 상담 화면에 타설명·현장을 표시한다. 다른 회차로 바꿀 때 현재 대상이 명확해야 한다.
- 추천 질문: ‘목표 강도 도달 예상은?’, ‘공시체 결과가 반영됐나요?’, ‘예측의 근거를 설명해 줘’.
- 답변 순서: 요약 → 수치와 기준 시각 → 근거 보기. 근거는 실제 응답에서 제공된 예측·문서만 표시한다.
- 도구 호출 인자·소요 시간 등 기술 정보는 접힌 상세 영역에 둔다.
- 현재 대화는 새로고침 시 사라진다. 대화 저장은 별도 구현 항목이며 저장된 것처럼 표시하지 않는다.

## 13. 데이터·상태 표현과 검수 기준

- 예상 시각이 없으면 ‘예측 불가’ 또는 구체적인 데이터 부족 사유를 표시한다. 미도달·조회 실패·입력 누락을 같은 상태로 취급하지 않는다.
- ‘90% 범위’는 예측 불확실성 표시이며 해체 안전 확률이나 승인 확률로 설명하지 않는다.
- 데이터 지연 판정 시간, 센서 별칭 저장, 현장 선택 범위, AI 회차 전달 방식은 API와 운영 기준을 확인한 뒤 구현한다. 데이터가 없으면 임의의 값으로 채우지 않는다.
- 예시 모드는 사용자가 선택하며 모든 관련 화면에서 예시임을 표시한다.
- 자동 메일 발송, 실시간 DB 연동, 사용자 권한, 현장 해체 승인 기록은 이 문서에서 구현된 기능으로 간주하지 않는다.

완료 점검:

- [ ] 첫 화면에서 확인할 타설과 다음 행동이 명확하다.
- [ ] 해당 부재의 목표 도달 예상·보수적 시각을 그래프를 해석하지 않고 찾을 수 있다.
- [ ] ‘예측 기준 도달’이 ‘현장 승인’으로 오인되지 않는다.
